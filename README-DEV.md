# TTAds Hub — разработка и проверка

Расширение — папка `TTAds-Hub` (в ней `manifest.json`): `chrome://extensions` → «Режим разработчика» → «Загрузить распакованное расширение».
Всё остальное в этом проекте — инструменты проверки. В расширение они не входят и ничего не отправляют наружу.

## Установка инструментов

Нужны Node.js 20+ и Chrome. Один раз:

```powershell
npm install
```

## Команды

| Команда | Что проверяет | Нужен Chrome |
|---|---|---|
| `npm run check` | синтаксис JS, валидность JSON, связывание модулей, соответствие вызовов интерфейса обработчикам service worker, неизменность набора разрешений manifest | нет |
| `npm test` | юнит-тесты: разбор страниц оплаты и таблиц BC, модель здоровья РК, контракты запросов, классификатор ошибок, настройки | нет |
| `npm run test:dom` | DOM-контракты Manual (legacy и unified редакторы), выбор переключателя Smart+ | да |
| `npm run smoke` | загрузка расширения, запуск service worker, отрисовка всех девяти разделов (скриншоты в `test-output/smoke`) | да |
| `npm run test:e2e` | сквозные сценарии на локальном «TikTok» (см. ниже) | Chromium / Chrome for Testing |
| `npm run verify` | всё перечисленное подряд | да |
| `npm run build` | `dist/TTAds-Hub-<версия>-complete-<дата>.zip` (расширение + инструменты, без `node_modules`) | нет |

Путь к Chrome ищется по стандартным местам, иначе задайте его:

```powershell
$env:CHROME = "C:\Program Files\Google\Chrome\Application\chrome.exe"
```

`test:e2e` запускает браузер с флагом `--load-extension`, который Chrome 137+ с брендингом отключил. Для него возьмите Chromium или Chrome for Testing
(`npx @puppeteer/browsers install chrome@stable`, затем `CHROME=<путь к chrome>`). `smoke` работает и с обычным Chrome.

## Как устроены сквозные сценарии

`tests/e2e/mock-tiktok.mjs` поднимает HTTPS-сервер на `127.0.0.1:8443` с самоподписанным сертификатом, созданным в памяти. Chrome стартует с `--host-resolver-rules`,
поэтому `ads.tiktok.com`, `business.tiktok.com` и `business-api.tiktok.com` ведут на этот сервер. Настоящий TikTok не затрагивается, личных данных в тестах нет.
Страницы мока — упрощённые аналоги живых: проверяется механика движков, а не вёрстка TikTok.

| Сценарий | Что проверяется |
|---|---|
| `overview-health` | проверка всех РК через фоновые вкладки: статус, карта, билл, долг, баланс; фильтры; выбор РК; профили конвейера |
| `auto-health` | автопроверка по таймеру и оповещение о новой проблеме; выбор объектов; разделы настроек; диагностика без ID |
| `objects-bulk` | обучение вкл/выкл, имени и бюджета по настоящему запросу произвольной формы; предпросмотр; применение; откат; отказ сервера |
| `objects-learn-edge` | тело запроса с ID числами (отклоняется), кириллица, обычный путь |
| `objects-reliability` | лимит 429 с повтором, потерянный ответ (изменение применилось), 401, «ок» без эффекта, смена адреса (404), возраст контракта |
| `manual-flows` | Manual в unified-редакторе: отказ сохранения → Smart+ через DOM, защита Sales → App, подпись переключателя из настроек |

Один сценарий: `node tests/e2e/objects-bulk.mjs`. Скриншоты — в `test-output/e2e`.

## Что не проверено автоматически

- Тексты страниц оплаты и Finance живого TikTok: разбор опирается на формулировки из исследования; порог автоплатежа («Billing / Payment threshold») — предположение.
- Реальные тела мутаций (вкл/выкл, имя, бюджет): расширение запоминает их у самого TikTok, заранее они не известны.
- DOM-сценарии создания BC и РК, шаринга, transfer и Payment Portfolio на живом TikTok. Для них у вас есть отдельный harness версии 1.5.0 (`e2e.mjs`, сценарии A–D).
