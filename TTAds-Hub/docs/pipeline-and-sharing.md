# Конвейер «создать → общая карта → расшарить» (TTAds Hub 1.5.0)

## Сценарий для пользователя

1. Вкладка **Создать** → выбрать «BC + РК» (новый Business Center с первым РК) или «РК в BC» (новый РК в существующем BC).
2. Указать количество (1–20) и шаблоны имён: `{date}` — ММДД, `{time}` — ЧЧММ, `{n}` — номер в пачке, `{rand}` — 4 случайных символа (одинаковые для пары BC/РК).
3. По желанию включить:
   - **Подключить общую карту** — на шаге Payment setup подтверждается Payment Portfolio, который TikTok сам предложил. Реквизиты карты расширение не видит и не хранит.
   - **Расшарить в другой BC** — выбрать сохранённого получателя или ввести ID BC, права Admin / Operator / Analyst; галочка «Сразу принять приглашение», если вы админ и в BC получателя.
4. Нажать одну кнопку. Окно можно закрыть: задача выполняется в сервис-воркере, прогресс хранится в `chrome.storage.local`.
5. Готовые кабинеты появляются в списке **Созданные РК**: отметить → «Расшарить», скопировать ID, выгрузить CSV.

Кнопка «BC + РК в один клик» на вкладке «Обзор» запускает тот же конвейер с сохранёнными настройками (1 штука, новый BC).

## Как это работает

| Шаг | Где | Механизм |
| --- | --- | --- |
| Создание | `business.tiktok.com/account/create` | DOM официального мастера (`background/creation/page-scripts.js`), как в 1.4.0 |
| Общая карта | `/account/payment-setup` | `Confirm` у Portfolio, который показал TikTok; уход вкладки со страницы после Confirm считается успехом |
| Шаринг | `/manage/company/partner?org_id={BC владельца}` | `Add partner` → ID получателя → дождаться карточки BC → `Next` → «Advertiser accounts» → отметить РК → права → финальный `Next`. Если получатель уже партнёр — его строка → `Share assets` |
| Принятие | `/manage/company/partner?org_id={BC получателя}` | выбрать строку `Pending approval` → `Approve` |

- На живом интерфейсе 28.10.2026 старый маршрут `/manage/partner` перенаправляется на `/manage/company/partner`; движок принимает оба варианта. `/api/v3/bm/partner/add` и `/partner/asset/update` защищены SecureSDK (проверка личности), поэтому шаринг выполняется через интерфейс, а не прямыми POST.
- Подписи кнопок TikTok различаются между версиями (`Add partner`/`Add`, `Assign`/`Confirm`, `Admin`/`Administrator`), поэтому каждый шаг перебирает несколько вариантов. Вкладки со счётчиком («Pending invitations (2)») ищутся по вхождению.
- Все функции страницы самодостаточны (сериализуются `chrome.scripting`) и запускаются через `runInPageGuarded`: если страница ушла полной навигацией или молчит дольше таймаута, сценарий не зависает.

## Состояния

- Конвейер (`pipelineJob`): `running → paused (нужна проверка TikTok) → running → complete | partial | error | cancelled`; `interrupted`, если Chrome перезапускал сервис-воркер. Элементы: `queued → creating → created → paying → sharing → done | error | cancelled`, а также `paused` / `share-paused`.
- Шаринг (`shareLastJob`): `running → complete | partial | needs-user | error | interrupted`. «Повторить» проходит только неуспешные пары «BC → получатель».
- Реестр (`createdAssets`): до 500 последних РК с BC, Portfolio и статусами шаринга (`invited` / `shared` / `accepted`).

## Когда нужен человек

- CAPTCHA, код на телефон/почту, проверка личности: вкладка выводится на передний план с подсказкой, конвейер ждёт «Продолжить». Коды и CAPTCHA не обходятся и не сохраняются.
- Нет прав Admin в исходном BC, РК не Approved, лимиты TikTok на число BC/РК или партнёров: шаг завершается ошибкой TikTok, вкладка остаётся открытой.
- Нет доступа к BC получателя: шаринг выполнен, приглашение нужно принять админу получателя (статус «ждёт принятия»).

## Диагностика

При сбое шага результат содержит `step`, `trail` (пройденные шаги) и снимок видимых заголовков/кнопок/полей (длинные числа маскируются). Кнопка «Скопировать диагностику» на карточке шаринга копирует его для быстрой правки подписей.

## Проверка

`tools/` (вне папки расширения) содержит smoke-тест всех вкладок и e2e-тест на локальном HTTPS-моке `business.tiktok.com` / `ads.tiktok.com` (`tools/mock-tiktok.mjs`). Мок повторяет задокументированные в `research-2026-10-28` подписи и структуры, но это не настоящий TikTok: подписи шага Partners после изменений TikTok нужно сверять на живом аккаунте.
