# Официальный Marketing API TikTok (v1.3): что подтверждено для TTAds Hub

Собрано 28 октября 2026 года из официальных docs, официального SDK и независимых клиентов (Airbyte и др.). **Живых вызовов с рабочим токеном не делалось** (только ответы-ошибки на фиктивные данные): формы успешных ответов взяты из документации и SDK. Это справочник для следующей итерации, а не часть работающего кода 1.6.0; расширение пока использует сессию Ads Manager и DOM (см. `../research-2026-10-28/`).

Файлы: `core.md` (OAuth, статус и баланс РК, отчёты, платежи, ошибки и лимиты), `structure.md` (кампании и адсеты: поля, ограничения, копирование), `ads-assets.md` (объявления, медиа, identity, pixel). В каждом есть источники и список неподтверждённого.

## Что важно для планов

1. **Карта и порог автоплатежа через API недоступны.** Нет ни одного документированного endpoint или поля. Поэтому в 1.6.0 они читаются со страницы оплаты (DOM). Косвенные признаки: транзакции `CARD_VERIFICATION`, счета `AUTO_PAY`. Статус аккаунта (13 значений `STATUS_*`), баланс, расход и платежи в API есть: `GET /advertiser/info/`, `GET /bc/asset/admin/get/` (нужен BC Admin), `GET /advertiser/balance/get/`, `GET /report/integrated/get/`, `GET /bc/account/transaction/get/`.
2. **Токен долгоживущий, без refresh.** Обмен `auth_code` и `GET /oauth2/advertiser/get/` требуют `secret` приложения, который нельзя прятать в расширении: нужен свой сервер или ключи, которые вводит пользователь. Лимиты считаются на приложение и endpoint: Basic 10 QPS / 600 QPM / 864 000 QPD, коды `40100`, `40016`, `40133`.
3. **Кросс-аккаунтного копирования нет.** `POST /campaign/copy/task/create/` работает внутри одного `advertiser_id` и только по allowlist. Перенос = чтение источника + создание в целевом РК (выключенным), с пересопоставлением pixel, identity, медиа, аудиторий и CTA-портфелей. Медиа можно официально расшарить по `material_id` (`POST /creative/asset/share/`), новые `video_id` придётся искать в целевом РК.
4. **С 1 января 2027 года** `/campaign/create/`, `/campaign/copy/task/create/`, `/adgroup/create/`, `/ad/create/` перестанут создавать и копировать legacy Manual-кампании для Sales, App Promotion и Lead Generation; нужен Upgraded Smart+ (`/smart_plus/...`) с другими полями. Для TRAFFIC срок неоднозначен.
5. **Custom identity (`CUSTOMIZED_USER`)** выводится из использования для Automatic/Select placement; `BC_AUTH_TT` для каждого РК нужно привязывать отдельно.
6. **Осторожно с числами.** `page_id` и `tracking_pixel_id` приходят JSON-числами из ~19 цифр, `JSON.parse` их округляет. В 1.6.0 перехваченные тела с такими числами не принимаются.
7. Бюджет в API нельзя установить ниже ~105% уже потраченного; ID в создании — строки; успех определяется полем `code`, а не HTTP-статусом.
